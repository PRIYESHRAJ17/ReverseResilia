## 1. Executive Summary

When severe disruptions strike supply chains — facility fires, arterial corridor shutdowns, flash floods, or sudden labor strikes — operational planners face urgent, high-stakes decisions:
- *How many customer deliveries can still arrive on time?*
- *Can spare inventory and capacity across surviving distribution centers absorb the shock?*
- *What is the maximum natural recovery possible with zero emergency budget?*
- *If executive management mandates a 100% service target, what is the exact minimum modeled expenditure?*
- *Can the recovery plan be mathematically proven feasible rather than accepted on faith?*

**ReverseResilia** is an enterprise-grade decision support platform that solves post-shock recovery through **exact mathematical optimization**. Powered by **Google OR-Tools CP-SAT** and **HiGHS Mixed-Integer Programming**, coupled with an independent **10-Point Zero-Trust Verifier**, ReverseResilia computes provably optimal reassignments, prices discrete emergency interventions, and certifies that every delivery promise is physically and financially sound.

- **Core A — The Decision Solver (Google OR-Tools CP-SAT & HiGHS MIP)**:
  Executes staged integer and constraint programming to establish mathematically provable natural recovery bounds, followed by minimum-cost target pricing.

  Runs client-side neural language models (Qwen 2.5 / SmolLM2) directly in the browser via WebGPU to translate mathematical constraints into actionable tactical directives without transmitting proprietary data to third-party cloud APIs.
- **The Zero-Trust Verifier**:
  An independent, standalone audit harness that evaluates candidate solutions against 10 physical and operational invariants before any plan can be executed or exported.

### ⚡ Comprehensive Disruption Simulation
- **Facility Outages**: Simulate complete warehouse destruction or shutdown.
- **Arterial Corridors**: Sever critical transport links and compute detour penalties.
- **Capacity Degeneration**: Degrade warehouse throughput or labor availability by discrete percentages.
- **Stock Depletion**: Test inventory stockout shocks across designated SKUs.

### 📊 Strategic Dual-Plan Optimization
- **Plan A — Natural Recovery (Zero Emergency Budget)**:
  - *Stage A*: Maximizes on-time order deliveries using only surviving, unassisted network capacity.
  - *Stage B*: Minimizes operational delivery costs while holding the proven maximum service level constant.
- **Plan B — Target Recovery (Priced Interventions)**:
  - *Stage C*: Evaluates a discrete catalog of emergency recovery packages (express air/road logistics, secondary warehouse activation, third-party logistics spot contracts, overtime labor shifts) to reach an executive target service level (up to 100%) at the absolute minimum expenditure.

### 🩺 Self-Healing CSV Repair Doctor
- Ingests customer order and warehouse CSV files.
- Automatically handles header discrepancies, case sensitivity, extra columns, and missing optional fields.
- Provides an interactive visual side-by-side diff modal allowing operators to preview, validate, and apply repairs before optimization.

### 📄 One-Click Executive Boardroom Brief & Vector PDF Export
- Generates a publication-grade executive brief with a single click.
- Features a **Strategic Decision Matrix** comparing Plan A vs Plan B across Service Recovery %, Total Expenditure, Cost per Recovered Order, and Required Interventions.
- Includes 4 executive KPI callout cards, the 10-point Zero-Trust mathematical verification audit stamp, and formal CSCO / Operations Commander signature blocks.
- Formatted with `@media print` CSS for pristine, vector-sharp PDF generation.

### 🌌 Cinematic 3D Operations Showcase
- Interactive WebGL Three.js particle galaxy with real-time orbit controls.
- Smooth kinetic scrolling with performance-optimized GPU compositing.
- Real-time operations desk with live engine telemetry HUD and embedded recovery dock.

## 5. Quickstart Guide

### Prerequisites
- **Python**: 3.12 or newer
- **Node.js**: 20.x or 22.x+
- **Git**

---

### Step 1: Start the Mathematical Optimization Engine

Open a terminal and navigate to `ReverseResiliaEngine`:

```bash
cd ReverseResiliaEngine

# Set up Python virtual environment
python -m venv .venv

# Activate virtual environment
# Windows (PowerShell):
.\.venv\Scripts\Activate.ps1
# Linux / macOS:
source .venv/bin/activate

# Install dependencies
pip install -r requirements.txt

# Start the FastAPI engine (serves API and pre-built UI)
python -m uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

The Decision Engine is now active:
- **API Documentation (Swagger UI)**: [http://localhost:8000/docs](http://localhost:8000/docs)
- **Standalone Recovery Desk**: [http://localhost:8000](http://localhost:8000)

---

### Step 2: Start the Showcase & Command Portal

Open a second terminal and navigate to `reverse-resilia/frontend`:

```bash
cd reverse-resilia/frontend

# Install dependencies
npm install

# Start Vite development server
npm run dev
```

The Command Portal is now running at:
- **Showcase & Command Portal**: [http://localhost:5173](http://localhost:5173)

---

### Step 3: Production Builds

To compile production-optimized bundles for static hosting or CDN deployment:

```bash
# Build Showcase Frontend
cd reverse-resilia/frontend
npm run build

# Build Optimization Desk Frontend
cd ../../ReverseResiliaEngine/frontend
npm run build
```

## 6. The 10-Point Zero-Trust Verifier

Before any mathematical solution is certified, it must satisfy all 10 independent verification criteria:

| Invariant | Name | Verification Condition |
|:---:|:---|:---|
| **I-01** | Non-Negative Allocations | All order flows and unit assignments $\ge 0$. |
| **I-02** | Warehouse Capacity Bounds | Total outbound volume does not exceed surviving warehouse capacity. |
| **I-03** | Inventory Conservation | Outbound stock does not exceed on-hand SKU inventory. |
| **I-04** | Disrupted Facility Isolation | Severed or offline warehouses have exactly 0 outbound assignments. |
| **I-05** | Severed Corridor Avoidance | Inactive road lanes are assigned 0 transit flow. |
| **I-06** | Hard Deadline Compliance | Delivery completion time $\le$ order deadline. |
| **I-07** | Single-Source Integrity | Each fulfilled customer order is served by exactly one valid facility. |
| **I-08** | Budget Ceiling Compliance | Total intervention expenditure $\le$ authorized budget limit (Plan B). |
| **I-09** | Priority Order Protection | Hard-priority critical deliveries are strictly prioritized over soft orders. |
| **I-10** | Deterministic Reproducibility | Input hash matches execution fingerprint; re-solving yields identical plan. |
